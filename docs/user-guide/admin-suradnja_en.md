# Tasks, comments, and notifications

These modules complement shared content. They do not each have a separate global Settings form; their controls appear where the feature is used.

## Enable the required feature

An administrator checks module installation and enablement in [Setup and modules](admin-podesavanje_en.md). Enabling a module does not grant everyone access to private pages. If a module or its dependencies are unavailable, address installation first rather than searching for a nonexistent global “Task settings” screen.

## Tasks

Authors add tasks to page content through the HTML editor. Users change task state only where permitted. Task state and history belong to that page; a task does not independently grant page access.

Check the same task as an editor and as a reader. For insertion and use, read [Editing pages](uredivanje-stranica_en.md).

## Comments

Comments and available actions depend on document access and its commenting settings. Signed-in users can participate only in the permitted context. Moderation and deletion require additional management checks; seeing a comment does not itself grant deletion rights.

Decide whether important pages need comments, then check their reader and moderator views. Reporting an inappropriate comment and deleting it are different actions. Deletion retains a moderation audit trail.

## Notifications

Users open their own **Notifications** to read them, mark all as read, or remove the offered records. Personal notification settings control their choices; administrators do not edit everyone's personal list in a shared form.

Email copies also require enabled [email delivery](admin-e-posta_en.md) and regular message processing. A notification must not bypass access to its private target: test its link with an account whose access has subsequently been removed.

## Following content

Where personal user features are available, a page's **Follow** control and personal delivery preferences help users follow content they may read. Following or subscribing does not grant new access. Read the [workspace guide](podrucja_en.md) for workspace and page procedures.

**Result of correct configuration:** collaborators use tasks, comments, and notifications within their permitted scope, without needing administrator accounts or exposing private content to others.

Practical user procedures: [Tasks](zadaci_en.md), [Comments](komentari_en.md), and [Following and notifications](pracenje-obavijesti_en.md).
