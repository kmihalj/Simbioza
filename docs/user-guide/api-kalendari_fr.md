# API — calendriers et événements

<a id="api--calendars-and-events"></a>


> Les captures d’écran présentent l’interface en anglais.

[← API — contenu](api-koristenje_fr.md)

`calendar:read` lit les calendriers accessibles au propriétaire de la clé. `calendar:write` complète les autorisations actuelles de création, d'écriture et de gestion. Un calendrier a besoin de `name` ; `type`/`calendar_type` peut être `personal`, `team` ou `resource`, sous réserve des règles de propriété et de gestion.

Les calendriers PATCH et DELETE nécessitent un ETag. ACL PUT accepte la liste `rules` complète : `subject_type` (`user`/`group`), numérique `subject_id`, `can_read`, `can_write`. Il remplace les règles directes, alors lisez l'état actuel avant d'écrire.

Un événement nécessite `title` et des valeurs de début/fin valides (`starts_at`, `ends_at`), avec `timezone`. `is_all_day` marque les événements d'une journée entière. Les variantes de date/heure et les alias sont répertoriés par opération. La récurrence utilise `recurrence_rule` ou des champs de fréquence/fin séparés. La plage d'événements GET nécessite `from` et `to` ; `expand_recurring=false` lit les définitions, tandis que l'expansion renvoie les occurrences. Les ID d'événement sont numériques, tandis que les chemins de calendrier utilisent un UUID.

L'importation ICS envoie le texte au format `ics`, numérique facultatif `calendar_id` et `merge_mode=skip` ou `update`. La création d'un calendrier au lieu de l'importer dans un calendrier existant est soumise aux autorisations et paramètres actuels. L'exportation ICS télécharge le calendrier ; cet route n'a pas de filtres `from/to`. Utilisez la liste d'événements pour le filtrage par plage de dates.

Ce REST API n'a pas d'opérations distinctes d'invitation, de réponse des participants ou d'approbation de réservation. L'ajout de tels champs à un événement normal POST n'appelle pas le flux de travail de réunion. [Les protocoles CalDAV et ICS](api-granice-protokola_fr.md) sont distincts du Bearer REST API.

**Objectif :** Renvoie les calendriers visibles par le propriétaire de la clé API.
