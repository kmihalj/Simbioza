# API v1 ugovor / API v1 contract

Ovaj dokument definira minimalni stabilni ugovor koji prethodi implementaciji
javnog HeartPhrame API-ja. Ne opisuje postojeće web controllere kao API.
Web rute ostaju namijenjene HTML sučelju, a API dobiva zasebne verzionirane
rute, autentikaciju, DTO objekte i pravila kompatibilnosti.

This document defines the minimum stable contract required before implementing
the public HeartPhrame API. It does not expose existing web controllers as an
API. Web routes remain dedicated to the HTML interface, while the API receives
separate versioned routes, authentication, DTOs, and compatibility rules.

## 1. Cilj i granice / Goal and boundaries

HR:

- API korijen je `/api/v1`.
- Prva verzija podržava JSON i UTF-8.
- Svaki domenski modul ostaje vlasnik svojih podataka, validacije i ACL odluka.
- `module-api` pruža zajednički HTTP sloj, ali ne čita izravno tablice drugih modula.
- Postojeće web rute i session prijava nisu javni API ugovor.
- API se može isključiti uklanjanjem `module-api`; ostali moduli nastavljaju raditi.
- API ključ ne može korisniku dati pravo koje nema u aplikaciji.

EN:

- The API root is `/api/v1`.
- The first version supports JSON and UTF-8.
- Every domain module remains the owner of its data, validation, and ACL decisions.
- `module-api` provides the shared HTTP layer but never reads another module's tables directly.
- Existing web routes and session login are not part of the public API contract.
- Removing `module-api` disables the API without breaking the other modules.
- An API key can never grant a user a permission they do not have in the application.

## 2. Vlasništvo modula / Module ownership

| Modul / Module | API odgovornost / API responsibility |
|---|---|
| `module-api` | Verzije ruta, JSON odgovori, problem responses, paginacija, OpenAPI, CORS, rate limiting, request ID i idempotency registar / Route versions, JSON responses, problem responses, pagination, OpenAPI, CORS, rate limiting, request IDs, and the idempotency registry |
| `module-auth` | API ključevi, autentikacija ključa, scopes, korisnički identitet, lokalni user/group CRUD i auth audit / API keys, key authentication, scopes, user identity, local user/group CRUD, and auth audit |
| `module-workspace` | Područja, stabla, čvorovi, workflow i Workspace ACL / Workspaces, trees, nodes, workflow, and Workspace ACL |
| `module-editor-html` | Dokumenti, jezici, verzije, HTML, privici i objavljeni prikaz / Documents, languages, versions, HTML, attachments, and the published view |
| `module-calendar` | Kalendari, događaji, ponavljanja, calendar ACL i ICS / Calendars, events, recurrence, calendar ACL, and ICS |
| `module-task` | Definicije zadataka, aktualna stanja i povijest promjena / Task definitions, current state, and change history |
| `module-notification` | Obavijesti trenutačnog korisnika / Current-user notifications |
| `module-email` | Nema javni endpoint za proizvoljno slanje pošte; ostaje interni servis / No public arbitrary-email endpoint; remains an internal service |
| `module-theme` | Opcionalni read-only opis aktivne javne teme / Optional read-only active public theme description |
| `module-menu` | Opcionalni read-only izbornik filtriran za trenutačni API identitet / Optional read-only menu filtered for the current API identity |

Domenski modul prijavljuje svoje API rute samo kada je `module-api` instaliran.
Opcionalna integracija ne smije postati njegova obavezna Composer ovisnost.

A domain module registers its API routes only when `module-api` is installed.
The optional integration must not become a required Composer dependency.

## 3. API identitet i ključevi / API identity and keys

Ključ je vezan uz postojećeg aktivnog korisnika. Autorizacija se provodi ovim
redoslijedom:

1. ključ postoji, nije opozvan i nije istekao
2. vlasnički korisnik postoji i aktivan je
3. ključ ima potreban scope
4. korisnik ima potrebno domensko pravo kroz postojeći ACL

A key belongs to an existing active user. Authorization is evaluated in this
order:

1. the key exists, is not revoked, and has not expired
2. the owning user exists and is active
3. the key contains the required scope
4. the user has the required domain permission through the existing ACL

Predloženi format ključa je:

```text
hfp_live_<public-id>_<secret>
```

`public-id` služi za pronalazak zapisa. Tajni dio generira se kriptografski
sigurnim generatorom, prikazuje samo jednom i u bazi se čuva isključivo njegov
hash. Nikada se ne zapisuje u audit, exception, access log ili HTML.

`public-id` locates the record. The secret is generated by a cryptographically
secure generator, displayed once, and only its hash is stored. It must never be
written to audit records, exceptions, access logs, or HTML.

Svaki ključ sadrži:

- naziv i opcionalni opis
- `user_id`
- skup scopes
- vrijeme isteka ili `null`
- `created_at`, `last_used_at`, `revoked_at`
- opcionalni popis dopuštenih IP adresa
- javni prefiks za sigurno prepoznavanje ključa u administraciji

Each key contains:

- a name and optional description
- `user_id`
- a set of scopes
- an expiration timestamp or `null`
- `created_at`, `last_used_at`, and `revoked_at`
- an optional IP allowlist
- a public prefix for safe identification in administration

## 4. Scopes

Početni registar koristi stabilne ASCII nazive:

```text
workspace:read
workspace:manage
page:read
page:write
page:publish
attachment:read
attachment:write
calendar:read
calendar:write
task:read
task:write
users:read
users:create
users:update
users:delete
groups:read
groups:manage
notifications:read
notifications:write
webhooks:read
webhooks:manage
```

`page:write` obuhvaća kreiranje stranice i njezina prvog nacrta, izmjenu ili
odbacivanje nacrta, prijevod, vraćanje verzije i brisanje. `page:publish` je
zasebno pravo pregleda i objave. `groups:manage` obuhvaća kreiranje, izmjenu i
brisanje grupa te dodavanje i uklanjanje članova.

`page:write` covers creating a page and its first draft, editing or discarding
a draft, translation, version restoration, and deletion. `page:publish` is the
separate review and publication permission. `groups:manage` covers group
creation, updates, deletion, and adding or removing members.

Administratorski status sam po sebi nije dovoljan za API operaciju. Ključ
aktivnog administratora mora imati i odgovarajući scope. `users:*` i
`groups:*` endpointi rade samo s lokalnim Auth zapisima; ne upravljaju
korisnicima u SAML, CAS, OIDC ili OAuth provideru.

Administrator status alone is not sufficient for an API operation. A key owned
by an active administrator must also contain the required scope. `users:*` and
`groups:*` endpoints operate only on local Auth records; they do not manage
users in SAML, CAS, OIDC, or OAuth providers.

`DELETE /users/{id}` deaktivira lokalni račun i opoziva njegove API ključeve.
Fizičko brisanje nije API operacija jer bi prekinulo audit, vlasništvo i
povijesne reference.

`DELETE /users/{id}` deactivates the local account and revokes its API keys.
Physical deletion is not an API operation because it would break audit,
ownership, and historical references.

## 5. Zajednički HTTP ugovor / Shared HTTP contract

### Zahtjev / Request

- `Authorization: Bearer <api-key>`
- `Accept: application/json`
- `Content-Type: application/json` za JSON body
- `Accept-Language` određuje zadani jezik odgovora
- eksplicitni `lang` parametar ima prednost za višejezični sadržaj
- `X-Request-Id` klijent može poslati, a server ga uvijek vraća

### Uspješan odgovor / Successful response

```json
{
  "data": {},
  "meta": {
    "request_id": "opaque-request-id"
  },
  "links": {}
}
```

Kolekcije koriste cursor paginaciju:

```text
page[limit]=50
page[after]=opaque-cursor
filter[...]=...
sort=field,-other_field
```

Zadani limit je `50`, a najveći `100`. Cursor je neproziran i klijent ga ne
smije rastavljati.

Collections use cursor pagination. The default limit is `50`, the maximum is
`100`, and cursors are opaque values that clients must not parse.

### Greška / Error

Greške koriste `application/problem+json` i stabilni strojno čitljiv `code`:

```json
{
  "type": "https://heartphrame.example/problems/forbidden",
  "title": "Forbidden",
  "status": 403,
  "detail": "The current identity cannot read this resource.",
  "code": "resource_forbidden",
  "request_id": "opaque-request-id"
}
```

Produkcijski odgovor ne sadrži SQL, stack trace, filesystem putanje ni tajne.

Production responses never contain SQL, stack traces, filesystem paths, or secrets.

### Vrijeme i identifikatori / Time and identifiers

- Datumi u JSON-u koriste ISO 8601 i UTC, primjerice `2026-07-28T12:00:00Z`.
- Identifikatori su JSON stringovi i smatraju se neprozirnima čak i kada je
  interni ključ broj.
- Prikazni naziv ili slug nikada nije zamjena za stabilni identifikator.

- JSON timestamps use ISO 8601 in UTC, for example `2026-07-28T12:00:00Z`.
- Identifiers are JSON strings and remain opaque even when the internal key is numeric.
- A display name or slug never replaces a stable identifier.

## 6. Konkurentne izmjene / Concurrent changes

Promjenjivi resursi vraćaju `ETag`, a izmjena traži odgovarajući `If-Match`.
Editor dodatno zadržava eksplicitni `draft_revision` za domensku zaštitu nacrta.
Zastarjeli ETag vraća `412 Precondition Failed`, a sukob draft revizije
`409 Conflict`.

Mutable resources return an `ETag`, and changes require a matching `If-Match`.
Editor additionally retains explicit `draft_revision` domain protection.
A stale ETag returns `412 Precondition Failed`, while a draft revision conflict
returns `409 Conflict`.

POST operacije koje klijent može ponoviti podržavaju `Idempotency-Key`.
Isti korisnik, endpoint i ključ zahtjeva moraju vratiti prethodni rezultat bez
ponavljanja poslovne operacije.

POST operations that clients may retry support `Idempotency-Key`. The same
user, endpoint, and request key must return the previous result without
repeating the business operation.

## 7. Početni resursi / Initial resources

### Read-only v1 jezgra / Read-only v1 core

```text
GET /api/v1/me
GET /api/v1/workspaces
GET /api/v1/workspaces/{workspaceId}
GET /api/v1/workspaces/{workspaceId}/tree
GET /api/v1/pages/{pageId}
GET /api/v1/pages/{pageId}/attachments
GET /api/v1/calendars
GET /api/v1/calendars/{calendarId}
GET /api/v1/calendars/{calendarId}/events
GET /api/v1/tasks
GET /api/v1/tasks/{taskId}
GET /api/v1/notifications
```

Kolekcije sadrže samo resurse koje vlasnik ključa smije vidjeti. Pojedinačni
nedostupan resurs vraća `404` kada bi `403` otkrio postojanje privatnog
resursa.

Collections include only resources visible to the key owner. An inaccessible
single resource returns `404` when `403` would reveal the existence of a
private resource.

### Administracija lokalnih korisnika / Local user administration

```text
GET    /api/v1/users
POST   /api/v1/users
GET    /api/v1/users/{userId}
PATCH  /api/v1/users/{userId}
DELETE /api/v1/users/{userId}
GET    /api/v1/groups
POST   /api/v1/groups
PATCH  /api/v1/groups/{groupId}
DELETE /api/v1/groups/{groupId}
PUT    /api/v1/users/{userId}/groups
```

Ovi endpointi zahtijevaju aktivnog lokalnog administratora i odgovarajuće
`users:*` ili `groups:*` scopes. API ne vraća `password_hash`, provider tajne,
reset tokene niti osjetljivu konfiguraciju. Lozinka se prima samo pri kreiranju
ili izričitoj promjeni i nikada se ne vraća.

These endpoints require an active local administrator and the corresponding
`users:*` or `groups:*` scopes. The API never returns `password_hash`, provider
secrets, reset tokens, or sensitive configuration. A password is accepted only
when creating a user or explicitly changing it and is never returned.

## 8. Write operacije / Write operations

Nacrti, objava, privici, događaji i zadaci dostupni su preko domenskih ruta:

```text
POST  /api/v1/workspaces/{workspaceId}/pages
PATCH /api/v1/pages/{pageId}/draft
POST  /api/v1/pages/{pageId}/review
POST  /api/v1/pages/{pageId}/publish
POST  /api/v1/pages/{pageId}/attachments
POST  /api/v1/calendars/{calendarId}/events
PATCH /api/v1/calendar-events/{eventId}
PATCH /api/v1/tasks/{taskId}/state
```

Drafts, publishing, attachments, events, and tasks are available through the
domain routes listed above.

### Webhook pretplate / Webhook subscriptions

```text
GET    /api/v1/webhooks
POST   /api/v1/webhooks
GET    /api/v1/webhooks/{uuid}
PATCH  /api/v1/webhooks/{uuid}
DELETE /api/v1/webhooks/{uuid}
POST   /api/v1/webhooks/{uuid}/rotate-secret
GET    /api/v1/webhooks/{uuid}/deliveries
GET    /api/v1/webhooks/{uuid}/deliveries/{deliveryUuid}
POST   /api/v1/webhooks/{uuid}/deliveries/{deliveryUuid}/retry
```

Mutacija se dovršava prije mrežne isporuke. API sprema sanitizirani događaj u
outbox, a CLI worker ga potpisuje HMAC-SHA256 potpisom i šalje uz ograničeni
retry. Tajna je šifrirana u bazi i vraća se samo pri kreiranju ili rotaciji.

A mutation completes before network delivery. API stores a sanitized event in
the outbox, and a CLI worker signs it with HMAC-SHA256 and sends it with bounded
retry. The secret is encrypted at rest and returned only at creation or
rotation.

## 9. Kompatibilnost / Compatibility

- Nova polja u response objektu dopuštena su unutar `v1`.
- Postojeća polja ne mijenjaju tip ni značenje unutar `v1`.
- Uklanjanje ili promjena značenja zahtijeva `/api/v2`.
- Novi opcionalni endpoint ne zahtijeva novu glavnu verziju.
- OpenAPI opis generira se iz istog registra koji registrira runtime rute.
- Interni PHP service signature nije automatski dio javnog HTTP ugovora.

- New response fields may be added within `v1`.
- Existing fields do not change type or meaning within `v1`.
- Removing or redefining a field requires `/api/v2`.
- A new optional endpoint does not require a new major API version.
- OpenAPI is generated from the same registry that registers runtime routes.
- An internal PHP service signature does not automatically become part of the public HTTP contract.

## 10. Sigurnosni minimum / Security minimum

Prije prvog javnog write endpointa moraju postojati:

- hashirani ključevi i prikaz tajne samo jednom
- opoziv i istek ključa
- scope i domenska ACL provjera
- rate limiting po ključu i IP adresi
- audit svih write operacija i neuspjelih autentikacija
- ograničenje veličine requesta
- sigurna validacija MIME tipa za upload
- CORS isključen po zadanom
- zaštita osjetljivih podataka u logovima i problem responseu

Before the first public write endpoint is enabled, the implementation must
provide:

- hashed keys with one-time secret display
- key revocation and expiration
- scope and domain ACL checks
- rate limiting per key and IP address
- audit of write operations and failed authentication
- request-size limits
- safe MIME validation for uploads
- CORS disabled by default
- protection of sensitive data in logs and problem responses
