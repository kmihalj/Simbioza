Simbioza 0.3.0: configuration and portable data

Version 0.3.0 is the clean initial release. Install it with a new database and newly prepared configuration and data directories. Upgrading from 0.2.x, restoring old Simbioza archives, or copying their configuration is not supported. Importing external Confluence XML exports remains available.

The application bootstrap reads framework.php in the application root. Set HPH_CONFIG_PATH there or in the process environment. Configuration layers listed in HPH_CONFIG_OVERRIDE_PATHS override earlier values. If no external directory is selected, the application uses its config directory. Private configuration belongs in that selected directory, not under data or in module source code.

Each module owns a subdirectory: for example HPH_CONFIG_PATH/auth/auth.json, HPH_CONFIG_PATH/email/email.json, HPH_CONFIG_PATH/editor-html/editor-html.json, HPH_CONFIG_PATH/workspace/workspace.json, and the menu, theme, calendar, api and backup subdirectories. Use the current documented JSON/PHP file format for each module. Never execute JSON as PHP. GUI settings read and write the same configuration; a correctly edited file is not a separate copy of GUI settings.

Auth login settings, user-attribute definitions and SSO profiles are in auth.json. Profiles are grouped under providers.<protocol>.profiles. The database retains users, groups, provider/profile identities and the attribute projection; removing an attribute definition removes its projection. Private SSO secrets must not be committed. Configure external SimpleSAMLphp paths according to the Auth documentation.

Workspace content is stored under data/workspaces/<storage-label>--<id>/pages/<page-label>--<uuid>/. Filesystem HTML belongs in content; attachments belong in attachments. Workspace/page menus and themes belong with their owning data. In database HTML mode the content is in the database, but attachments remain files. data/editor-html is for independent Editor documents, not an alternative copy of workspace pages. Switching the HTML storage mode uses the supported GUI operation and preserves the current ownership layout.

Current backup archives use format version 2 and include the source public site address. Restore to the same site preserves applicable links. Restore to another site resolves internal pages and attachments against imported identities, retains external links, and reports unresolved references for review. Do not replace the old domain globally or copy installation-specific absolute filesystem paths.

These instructions apply to mod_php, ordinary PHP-FPM and secured PHP-FPM. Give the relevant web/worker accounts access to the selected configuration layers and data directories; do not make the entire application world-writable. The screenshots illustrate GUI workflows and may show an earlier visual layout; the configuration paths and formats in this section are authoritative for 0.3.0.
